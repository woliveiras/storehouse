# Writing Blog Posts

Write for the target publication rather than imposing a generic house style.

## Process

1. Read repository instructions, content schema, existing authoring guidance,
   and representative recent posts before drafting.
2. Define audience, reader problem, intended outcome, claim/evidence boundary,
   language, voice, post shape, and publication status.
3. Use [technical-blog-structure.md](references/technical-blog-structure.md) to
   select tutorial, conceptual, or opinion structure.
4. Use [voice-and-style.md](references/voice-and-style.md) to infer and preserve
   author voice without copying sentences from the reference corpus.
5. For Astro/MDX targets, read [astro-mdx.md](references/astro-mdx.md).
6. Draft explicit, searchable titles and an introduction that establishes what,
   why, audience, and expected learning or action.
7. Prefer concrete examples, runnable commands, expected outcomes, trade-offs,
   limitations, primary sources, and honest uncertainty.
8. Validate with [quality-checklist.md](references/quality-checklist.md) and the
   target repository's own build/lint/content checks.

Do not invent lived experience, citations, measurements, credentials, quotes,
or publication authority. Drafting or editing does not authorize publishing.
