# Behavior/oracle matrix

Create the matrix as a separate artifact before implementation exposure. Use the bundled matrix template, routed from `SKILL.md`, when the project has no stronger convention.

Map each stable acceptance criterion and relevant normal, edge, invalid, compatibility, and recovery scenario to an invariant, observable oracle, oracle provenance, planned verification, and resulting evidence. A matrix exposes missing behavior and circular checks; it does not replace the full specification.
